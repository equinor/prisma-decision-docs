# Decision workflow

These page guides explain the possibilities available in Prisma, from framing a
decision to reviewing its model and assessing decision quality. Follow the
sequence below as a starting point, not a mandatory checklist: revisit earlier
work as new insights emerge, and use only the tools relevant to your decision.
Assess decision quality throughout the process, not just at the end.

## Before you start

Use the sign-in method configured for your Prisma deployment and confirm that
you have access to the intended project. In a demo, use non-personal training
identifiers and non-confidential data. Management controls depend on project
roles, so the facilitator's screenshots may show more buttons than a member sees.

Expand the sidebar to read the workflow labels while learning the application.
Changing light/dark mode affects presentation, not project inputs or results.

## Get started

1. [Get started](./get_started.md): create or import a project, find existing
   projects, and manage favorites.

## Frame the decision

2. [Project information](./project_information.md): state the opportunity,
   review the team, and manage settings.
3. [Objectives](./objectives.md): define, classify, and refine what the decision
   should achieve.
4. [Stakeholder matrix](./stakeholder_matrix.md): identify stakeholders and discuss
   their influence and how they are affected.
5. [Issues](./issues.md): capture and classify issues and define the model boundary.
6. [Whiteboard](./whiteboard.md): explore and organize issues collaboratively.
7. [Strategies](./strategies.md): combine decision options into courses of action
   and compare the combinations.

## Structure and explore the model

8. [Influence diagram](./influence_diagram.md): inspect the model structure,
   probability inputs, and calculated results.
9. [Decision tree](./decision_tree.md): expand branches to explore sequences of
   decisions and uncertain outcomes.
10. [Compact tree](./compact_tree.md): inspect an alternative, condensed tree view.
11. [Solution tree](./solution_tree.md): examine the solution representation.

The compact and solution trees are alternative views, not additional required
model-building steps.

## Assess and iterate

12. [Assessments](./assessments.md): create evaluation rounds, submit scores,
    review responses, and track progress.

Use [Assess decision quality](./decision_quality.md) for the six elements,
discussion prompts, and scoring guidance. Return to framing or model development
when an assessment identifies weaknesses that could change the decision.

## Before sharing a decision record

- Confirm the opportunity, objectives, boundaries, and decision authority.
- Check that arrows represent the intended dependencies and information timing.
- Review probability row sums, value inputs, units, and all required state
  combinations.
- Discuss expected value and downside rather than presenting an average as a
  guaranteed outcome.
- Save the model export, important results, assumptions, and review rationale
  separately. A JSON export is not a complete record of assessment submissions.
- Reopen or import a copy and check it before treating it as a validated model.

## Source and applicability

These guides incorporate applicable guidance from
[Make a decision with Prisma](../Prisma_Decision_User_How_To.docx), dated
30 October 2026, with controls and export coverage checked against the application
sources used for the current page guides.

The Word document also describes extended economics, financial-analysis,
sensitivity, information-value, and drilling interfaces that are not present in
the current captured application. Those screen-specific instructions and their
worked financial results have not been presented here as available or reproduced.
Unlike the older export limitation in the Word document, the current export
includes stakeholder-matrix entries.
