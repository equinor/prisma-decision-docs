## Understand which issues enter the diagram

The information popup explains which issues enter the influence diagram: Focus decisions, Key uncertainties, and Utility issues with boundary **in** or **on**. The boundary records a scope judgment for an issue; **on** means relevance is still uncertain, not that the issue is excluded. If an issue is missing from the diagram, check these inclusion settings and its options or outcomes before creating a duplicate issue.

Because these issues can feed directly into the influence diagram, define each one precisely enough to pass the clarity test described in [Building a diagram](../../domain/influence_diagram.md). Could someone identify what each state or value means without asking the team to interpret vague wording? State decisions as explicit choices, uncertainties as clearly defined outcomes, and utilities as values on an understood scale. Classification and boundary establish an issue's role and scope; they do not make an ambiguous issue precise.
